# 第二意见：先预览，再继续聊

在 A 已完成的回复旁邀请 B，也可以在同一位置分别邀请 C、D。意见先出现在面板内，点击“继续聊”才创建正式分支，沿用已经生成的提问和回复。原会话不切换模型，也不会自动收到其他模型的意见。

## 使用

回复操作栏的灰色图标打开“第二意见”。选择模型，可填写本次提问，再点击“邀请回应”。正文使用 DSH 的流式 Markdown；各意见可折叠，默认只展开一项，新邀请展开新项，后台完成不会切换正在阅读的意见。

生成中可停止，收到的文字保留在卡片中。具有已落定回复的意见可“继续聊”；只有未完成的流片段时保留预览，不将它冒充完整回复接入会话。同一意见再次继续聊会打开已有分支，后续追问不会增长原卡片。旧版本已经创建的分支仍可打开。

在“设置 → 第二意见”编辑默认提示词，点击保存生效，也可留空或恢复默认。本次提问非空时才追加相应引导和用户文字；默认提示词为空时直接使用本次提问。两者都为空时需要填写。面板可展开查看本次提示词，已有意见保留发起时的文本，不随设置更新。

## 安装与加载

在 DSH 插件页面添加本地目录 `E:\Projects\agent-workspace\agent-toolkit\deepseek-harness\plugins\dsh-second-opinion`，安装并启用。插件适用于桌面应用内的 Web 界面，没有前端构建步骤。直接从源码加载或运行离线测试前，在插件目录使用 `npm ci --ignore-scripts` 准备锁定的配置 schema 依赖。

模型调用只在邀请后发起，使用所选渠道的凭据和额度。代码更新后的加载按宿主插件管理流程进行，不通过重写用户配置或修改 DSH 本体完成。

## 上下文与执行

- 分支边界固定为所选回复所在的完成轮次，各模型继承该位置的有效历史，不互相继承意见。宿主处理已有 compact 替换和消息投影。
- 系统指导按 B 的选择重新组装，包括模型行为指南；运行环境信息按宿主规则刷新。固定聊天历史不等于复制 A 当时的整份模型请求。
- 意见使用未发布的宿主 Agent，沿用原会话 preset，不进入普通会话列表。咨询阶段限制工具并只允许一次生成步骤；宿主自动压缩和重试仍可能产生额外模型调用。
- 宿主 checkpoint 对临时意见的保存请求通过 Cordis accessor 接入意见快照，保存成功后才继续执行。普通会话仍调用宿主原有的 flush，意见结束后释放对应关联。
- 历史包含图片时，B 必须明确支持图片输入。不静默移除图片。
- 点击“继续聊”时正常创建和关联正式会话，接入保存的事件，后续使用 B 并恢复正常会话的工具能力。

内部接口集中在 `adapter.js`，适配 DSH Desktop **0.2.2-rc.3**。从原会话已加载的运行实例取得宿主驱动类，使用独立 Session、宿主消息投影及 preset 构造预览，通过 `agent.model.select()` 选择模型。预览使用自己的生命周期信号，随插件或宿主卸载停止并释放，不影响原会话。原会话没有运行实例时提示先通过 DSH 打开，不主动恢复旧会话或执行其待处理消息。DSH 升级时需核对该适配；设计取舍及核查依据见 [DESIGN.md](DESIGN.md)。

## 数据保存

运行数据位于 `$DSH_HOME/second-opinion`，未设置时使用 `~/.dsh/second-opinion`。`candidates.json` 保存意见状态、文字与分支关联，`opinions/` 保存各意见的固定历史和增量事件。固定历史写入一次，生成期间节流保存增量，不随每个 token 重写全部历史。运行数据包含聊天内容，不加入源码仓库。

重启后未完成的意见标记为中断，保留已保存内容，不自动重新请求模型。已经生成的旧版分支不迁移或删除。

## 文件职责

- `index.js`：插件配置与服务入口。
- `backend.js`：意见任务、接口、停止和继续聊。
- `adapter.js`：集中管理 0.2.2-rc.3 内部接口、预览生命周期与 preset／模型选择。
- `prompt.js`：默认提示词与动态组装。
- `history.js`、`store.js`：历史边界、结果提取和意见保存。
- `client.js`：宿主组件界面、流式预览和设置页。
