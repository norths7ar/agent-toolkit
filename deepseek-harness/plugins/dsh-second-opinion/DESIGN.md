# 第二意见设计与接口依据

2026-11-10 按已接受方案完成代码改造，并根据用户重启后的反馈修正工作区接口层级。使用及当前验证状态见 [README](README.md)。界面遵循[共享前端设计约定](../../docs/frontend-design.md)。

## 使用流程

在已完成回复的操作栏提供与宿主一致的图标入口。用户选择另一模型，可填写本次提问；发起后在原位置对应的面板内阅读意见。意见阶段不建立普通会话列表条目，点击“继续聊”才创建可继续的分支，并接入已经生成的提问和回复，不重新生成。

同一位置可分别邀请多个模型，各自使用相同的原会话锚点，不继承其他候选的意见。采用单项展开的折叠列表：主动邀请时展开新项，允许全部收起；后台完成只更新状态，不改变当前阅读项。标题显示模型的可读名称与状态，需要区分渠道时提供次要信息。正文使用宿主 Markdown，生成中逐步更新并提供“停止”。

## 提示词设置

通过宿主设置菜单提供“第二意见”页面，复用配置表单机制。默认提示词可编辑、清空和恢复默认，长文本编辑后点击保存。本次提问仍在邀请弹窗中填写。

默认内容为“请阅读以上讨论，给出你的看法。”。用户输入非空时，才追加“请围绕以下问题回答：”及用户原文；默认提示词为空时直接使用用户提问。两者都为空时提示填写。请求发起时冻结实际发送的文本，提供展开查看，后续设置修改不改变旧意见。

一次生成和工具限制由运行逻辑落实，与用户可编辑提示词分开。

## 上下文与生成路径

### 未发布的宿主 Agent

当前适配目标是 0.2.2-rc.3。宿主不提供 `agentLoop.prepare()`，普通 Agent 工厂会注册会话。插件从原会话已有运行实例取得驱动类，通过独立的 `Session.create()`、宿主 `messageProjections` 和运行时 projection readers 构造未注册 Agent；preset 安装后调用 `agent.model.select()`。预览为驱动提供独立的生命周期信号，释放时先终止该信号以阻止后续唤醒，再取消运行、等待空闲并释放 scope，同时跟随插件与宿主运行时的卸载。preset 安装期间若发生卸载，返回的 setup 不再提交。原会话的生命周期不受影响。用户接受的限制是原会话须已有运行实例；插件不为取得驱动类而主动恢复冷会话。

这条路径集中在 `adapter.js` 中，复用宿主的上下文组装、消息投影、请求钩子和流结果记录。它是内部接口适配，不是宿主公开承诺的暂存会话能力。preset 的 `mount()` 源码明确支持未发布 Agent，标准 preset 的关键成员已静态核查；完整部署插件的动态联动仍待验证。

宿主 checkpoint 策略在 `agent/pre-step` 调用 SessionStore.flush，而未发布 Session 不属于该 store。适配层通过 Cordis 的 `sessions.flush` accessor，仅将本插件登记的临时 Session 路由至意见快照保存；其他 Session 保留原方法及接收对象。持久保存失败仍阻止后续执行，不跳过 checkpoint 或其他 pre-step 插件。对应关联随临时 Agent 释放，accessor 随插件卸载清理。

上下文规则：

- 对话历史固定到所选回复所在的完成轮次，保存该锚点的事件前缀；原会话此后发生的变化不进入意见。
- 有效消息由宿主 Session 投影产生，沿用该前缀已有的压缩替换和消息投影，不把已被压缩替代的原文重复拼入请求。工具历史保留为历史上下文，咨询阶段不执行新工具。
- 系统指导按 B 的模型选择重新组装，使用当前生效的指南；不把 A 的历史指导当成 B 的配置。历史固定不等于所有运行时配置冻结到历史时刻。
- 沿用原会话 preset 和工作目录的组装路径；动态运行环境由宿主刷新。具体 preset 对未发布 Agent 的支持需在集成阶段确认。
- 在意见记录中保存实际请求、模型归属和生成事件，使卡片与后续分支有同一份来源。

`llm.stream()` 是公开的备选路径，可复用 Provider 与授权，但它不会自动执行完整的 Agent 系统指导和请求组装流程。若改用此路径，需要明确补足的上下文能力，不能无声改变模型指南的效果。

## 从意见转为会话

插件保存固定前缀和本次意见的完整事件。用户点击“继续聊”时，从这些记录创建普通会话，关联原工作区，并使后续请求继续使用 B。不重新提交咨询请求。

意见 ID 与分支 ID 持久关联，后续点击打开已有分支。实现时需处理同一意见的并发点击，以及创建会话和记录关联之间的中断。后续追问只增长新会话，不增长原卡片预览。

现有版本已经创建的候选分支继续保留并打开原分支；不因本次改造删除用户已经生成或追问的会话。

## UI 复用边界

宿主已向插件导出 `Modal`、`MarkdownText`、`DisclosureRow`、`Tooltip`、图标以及 `Button`、`Input`、`Menu` 等。模型选择器本身未导出，候选选择需用这些基础组件组合并保持独立状态，不修改主会话模型。

Windows 右上角窗口按钮属于原生标题栏。宿主 Modal 的网页遮罩不覆盖该区域；颜色同步属于桌面壳的单独问题，不将替换 Modal 描述为已经解决这一现象。

## 验证依据

新版离线集成脚本位于工作区根 `.tmp/20261114-dsh-rc3/dsh/verify.mjs`，使用实际安装的 0.2.2-rc.3 核心模块和模拟模型。验证固定源记录不变、未注册预览、B 指南、保存回复转分支和重复继续聊。preset 组合与工作区关联为模拟实现；以下 rc.5 实验保留为早期设计依据，不作为新版运行验收结果。

本轮使用安装包内的真实 rc.5 模块和合成数据，未调用真实模型，未读写用户会话：

- 未发布 Agent 实验通过 8 项断言：B 的指南进入请求、模型选择为 B、生成完成，且无 Session／Agent 注册、创建发布或持久化创建。LLM、工具与持久化服务为模拟实现；模型指南执行了现有插件的 apply 正文，未挂载完整部署 preset。
- 分支接入实验通过 9 项断言：固定前缀不泄漏后续消息；原咨询、意见 ID、正文、模型归属和流记录保留；JSON 文件保存后经宿主 Session 恢复一致；可追加追问；持久映射原型可重复打开同一分支。

实验脚本位于工作区根 `.tmp/20261110-opinion-context/probe.mjs` 与 `.tmp/20261110-opinion-promotion/verify.mjs`。它们是临时可行性证据，不是已落地的插件测试。映射实验不代表宿主自动提供幂等；JSON 恢复不代表已验证宿主重启。实际 Provider replay、工具历史、compact、部署插件以及桌面加载未在本轮动态覆盖。

实现后的集成实验位于工作区根 `.tmp/20261110-opinion-context/implementation-host-query.mjs`，直接执行插件的 `backend.js` 和 `adapter.js`，使用真实 Cordis、AgentLoop、Session、SessionQuery、Tools、宿主命令控制器实现和模拟模型；验证 B 的指南、工具限制、延迟创建正式会话、已有回复保留及重复打开。Controller 的 preset 组合在该实验中模拟，未将其描述为完整 preset 的实机测试。

仓库内离线测试覆盖历史边界、提示词配置、流式状态、继续聊、旧版分支、停止／卸载和恢复。独立审查核对了宿主 UI 组件契约、锚点 preset 继承与可继续状态。后续仍需在实际 DSH 中验收新界面、真实模型生成和宿主重启恢复。
