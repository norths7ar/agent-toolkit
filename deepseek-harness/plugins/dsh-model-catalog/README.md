# 模型目录

从提供商获取最新模型清单，比较参数后更新 DSH 中启用的模型。

这是 toolkit 内的本地原型，面向 DSH Desktop 0.2.2-rc.3。启用后，从侧栏打开「模型目录」，选择提供商并点击「获取模型」。勾选表示保留或添加，取消勾选表示移除；变更在确认保存后生效。

## 更新规则

已有配置值默认保留。「本地配置」与「提供商返回」逐项对照，可以单独采用上下文窗口或最大输出的新值。采用后保留差异标记，改过的模型可通过「未保存」筛选找回。提供商没给出的必需参数由用户补充。仅返回 ID 的已有型号显示为「已配置」，不代表参数已经核实。凭据和协议保持原样。

完整获取清单后，远端未返回的已有模型默认取消勾选，标记为「远端未返回」；可以重新勾选保留。请求失败或只返回部分清单时，不会据此取消勾选。保存前列出添加、修改与移除的模型供确认。

语音、图像生成、Embedding 等专用型号统一标记为「不支持接入」，仅展示，不提供勾选或参数编辑。分类优先使用接口元数据；MiMo 的 ASR、TTS 和 OpenAI 的语音、图像生成、Embedding 等专用型号按明确的命名规则识别。

已有模型按配置顺序置顶，其余聊天型号按系列、版本排序，同型号的日期快照放在非日期型号后，不支持接入的类型放在最后。目录提供下线日期时，名称旁显示日期标签。

每个提供商至少保留一个模型：DSH 将空模型列表解释为恢复内置目录，而不是停用全部模型。

查询只请求模型目录端点，不调用聊天或其他推理接口。需要鉴权时，在后端复用提供商已配置的凭据。

OpenCode Zen 使用已有 API Key 查询账户可用的模型清单，不需要另配基础地址；用户指定的自定义地址仍按其配置处理。

原型主要服务于 pi-ai 提供商。混合协议提供商中，内置目录不认识的新型号可能缺少协议信息；这类条目会提示原因，不会为了加入一个型号而修改整个提供商的协议。

## 开发

开发工具版本记录在 `.node-version`、`package.json` 和锁文件中。

```sh
npm ci
npm run check
```

`check` 执行 lint、格式检查和离线测试，不调用模型。界面遵循 [DSH 插件前端设计约定](../../docs/frontend-design.md)。
